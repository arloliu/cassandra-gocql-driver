# Upstream Issue/PR Triage Plan

> **For agentic workers:** This is a triage workflow, not an implementation plan. Execute task-by-task. The deliverable is the TODO artifact at `docs/upstream-triage/2026-05-17-todos.md`. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sweep upstream `apache/cassandra-gocql-driver` open issues and PRs to identify items relevant to our `otter-cache` fork, classify them by severity and applicability, and produce an actionable TODO artifact.

**Context:** Upstream is under-maintained (motivation for our fork to stop chasing merge-back). Their open backlog still surfaces real bugs, useful fixes, and feature requests worth mining as hints for our own hardening work. Many items may already be addressed by commits on our branch — verification against our tree is part of triage.

**Architecture:** Three-pass triage. Pass A walks open *issues* (signals of bugs in trunk we may share). Pass B walks open *PRs* (cherry-pick candidates). Pass C scans recently merged-to-trunk PRs that may not yet be incorporated into our base. Each pass classifies items with a fixed rubric and appends rows to the TODO artifact. A final consolidation pass ranks the survivors and pulls out the actionable shortlist.

**Tech Stack:** `gh` CLI, `git log`/`git grep` on local checkout, plain markdown for the artifact.

## Triage Rubrics

These are reused across every task — keep them stable so the TODO artifact is internally comparable.

### Severity (impact if hit in production)

| Code | Meaning | Examples |
|------|---------|----------|
| **S1** | Critical: panic crashing a Go process, data corruption, auth/security flaw | Panic in event-loop goroutine, malformed frame parser, retry that never terminates |
| **S2** | High: connection storms, infinite retries, goroutine/memory leaks, severe perf cliffs | Pool exhaustion on transient errors, `MaxRetries` ignored, leaks on `Iter.Close` skip |
| **S3** | Medium: incorrect-but-recoverable result in a narrow path, observability gaps, mild perf | `MapScan` returns wrong shape for UDT, `ObservedQuery` missing table |
| **S4** | Low: ergonomics, godoc errata, edge-case typos, minor bug in rarely-used helper | Function name in godoc wrong, helper accepts wrong type |
| **S5** | Info: support questions, feature requests we don't need, duplicates, abandoned threads | "How do I set pool size?", "Make gocqlx part of the package" |

### Relevance to `otter-cache`

| Code | Meaning |
|------|---------|
| **R1** | Already fixed on our branch — cite the commit |
| **R2** | Affects code paths our deployments use — investigate |
| **R3** | Affects code we touch, but workload makes impact low |
| **R4** | Out of scope: feature we don't use (LZ4/snappy compression internals, Scylla-only, etc.) |
| **R5** | Already handled differently in our fork (upstream PR superseded by our approach) |

### Action

| Code | Meaning |
|------|---------|
| **A1** | Fix on our branch soon (high impact + relevant + no upstream fix in flight) |
| **A2** | Investigate further: needs reproducer, code-read, or benchmark to decide |
| **A3** | Track upstream PR; cherry-pick when it merges to trunk |
| **A5** | Cherry-pick candidate: open PR is clean and applicable to our fork now |
| **A0** | No action (R1/R4 close it out) |

### TODO row format

````markdown
### [S?/R?/A?] #NNNN — Short title
- **Upstream:** https://github.com/apache/cassandra-gocql-driver/issues/NNNN (or /pull/NNNN)
- **Last activity:** YYYY-MM-DD
- **Summary:** 1–2 sentences in our words.
- **Our fork:** Already fixed in `<sha>` | Reproduces on otter-cache | Not applicable because … | Unknown — needs check.
- **Next step:** Concrete action (read X, write reproducer, cherry-pick, close-out note).
````

Severity ordering inside the artifact is descending: S1 first.

## Task 1: Snapshot the raw upstream backlog

**Files:**

```bash

  --json number,title,labels,createdAt,updatedAt,comments \
  --template '{{range .}}- #{{.number}} ({{.createdAt | timefmt "2006-01-02"}}, upd {{.updatedAt | timefmt "2006-01-02"}}, {{len .comments}} comments) {{.title}}{{"\n"}}{{end}}'
```

Append to `docs/upstream-triage/2026-05-17-raw.md` under heading `## Open issues`. If templating fails, fall back to a plain `--json number,title,createdAt,updatedAt | jq -r` invocation.

- [ ] **Step 2: Fetch open PRs**

Run:
```bash
gh pr list --repo apache/cassandra-gocql-driver --state open --limit 200 \
  --json number,title,labels,createdAt,updatedAt,isDraft \
  --template '{{range .}}- #{{.number}} ({{.createdAt | timefmt "2006-01-02"}}, upd {{.updatedAt | timefmt "2006-01-02"}}{{if .isDraft}}, DRAFT{{end}}) {{.title}}{{"\n"}}{{end}}'
```

Append to the raw file under `## Open PRs`.

- [ ] **Step 3: Fetch recently merged PRs**

Run:
```bash
gh pr list --repo apache/cassandra-gocql-driver --state merged --limit 100 \
  --search "merged:>=2025-06-01" \
  --json number,title,mergedAt,labels \
  --template '{{range .}}- #{{.number}} (merged {{.mergedAt | timefmt "2026-01-02"}}) {{.title}}{{"\n"}}{{end}}'
```

Append under `## Recently merged PRs (post-2025-06)`. The date is chosen because our branch already has Pre-summer-2025 trunk merged (last `Merge branch 'trunk'` commit on otter-cache is the divergence boundary — verify with `git log --merges otter-cache --grep 'trunk' --pretty='%h %s %ci' | head -3` and adjust the date if it landed before).

- [ ] **Step 4: Verify the raw file is non-empty and committable**

Run: `wc -l docs/upstream-triage/2026-05-17-raw.md`
Expected: at least ~60 lines (30 issues + 30 PRs + merged set).

- [ ] **Step 5: Commit the raw dump**

```bash
git add docs/upstream-triage/2026-05-17-raw.md
git commit -m "docs(triage): snapshot upstream open issues/PRs 2026-05-17"
```

## Task 3: First-pass classify open PRs (Pass B)

Same approach as Task 2, but for PRs. PRs that look like clean cherry-pick candidates get `A5`. Drafts and stalled (>180 days no activity) drop to `A3` (track only) unless severity is S1/S2.

- [ ] **Step 1: Walk every open PR and append a TODO row**

For each PR in `## Open PRs`:

1. Look at the title + first 200 chars of body:
   ```bash
   gh pr view <N> --repo apache/cassandra-gocql-driver --json title,body,labels,isDraft,files,additions,deletions
   ```
2. Classify. PRs touching code we modified (heartbeat path, retry path, frame parsers, host policy) get `R2` and need `A2` to evaluate against our local diff.
3. Append rows under `### PRs`. For `A5` candidates, set `Next step:` to "cherry-pick #NNNN onto otter-cache and verify against our hardening commits".

- [ ] **Step 2: Commit**

```bash
git add docs/upstream-triage/2026-05-17-todos.md
git commit -m "docs(triage): first-pass classify upstream open PRs"
```

## Task 4: Verify "our fork" status for every S1/S2/S3 row

For every row in the TODO artifact tagged `S1`, `S2`, or `S3` (not `S4/S5`, not in the no-action bucket), confirm whether the issue is already addressed on `otter-cache` or still reproduces.

**Heuristics for checking quickly:**

- [ ] **Step 1: For each S1/S2/S3 item, search our commits for matching keywords**

Use `git log` on otter-cache:
```bash
git log --oneline origin/trunk..otter-cache --grep '<keyword>'
git log --oneline origin/trunk..otter-cache -- '<filename glob>'
```

Examples to try:
- Issue mentions "panic" + "host filter" → `git log --grep -i panic --grep -i filter`
- PR touches `frame.go` → `git log -- frame.go`
- Issue mentions "retry"/"unprepared" → `git log --grep -i unprepared` (we already have `4808e09` + `31edd04`)

- [ ] **Step 2: For each item, grep current code state**

```bash
git grep -n '<symbol>' -- '*.go'
```

Confirm whether the relevant function still has the upstream-reported behavior or our patch shape.

- [ ] **Step 3: Update each row's `Our fork:` field**

Replace `Unknown — verify in Task 4` with one of:
- `Already fixed in <sha> ("<commit subject>")` → also bump action to `A0`, severity preserved for record-keeping
- `Reproduces on otter-cache as of <sha>` → keep action `A1`/`A2`
- `Not applicable because <reason>` → action `A0`
- `Diverged: our <commit-or-file> handles this differently; needs comparison` → action `A2`

- [ ] **Step 4: Commit the verification pass**

```bash
git add docs/upstream-triage/2026-05-17-todos.md
git commit -m "docs(triage): verify upstream issues against otter-cache state"
```

## Task 5: Recently merged PRs (Pass C — cherry-pick gap detection)

Anything merged to trunk after our last `Merge branch 'trunk'` commit but not present on otter-cache is a candidate for cherry-pick.

- [ ] **Step 1: Identify our trunk merge boundary**

Run:
```bash
git log --merges otter-cache --grep 'trunk' --pretty='%h %ad %s' --date=short | head -3
```

Note the date of the most recent trunk merge — that's our cutoff.

- [ ] **Step 2: Walk merged PRs after the cutoff**

For each entry in `## Recently merged PRs` whose merge date is after the cutoff:

1. Check if our branch already has the commit:
   ```bash
   git log otter-cache --grep 'CASSGO-NN' --oneline    # if PR title has a CASSGO ticket
   git log otter-cache --oneline -- <file PR touched>
   ```
2. If not present, classify with the same rubric. Bug fixes get `A5` (cherry-pick candidate); refactors/features default to `A3` unless they unblock something we need.
3. Append rows under `### Recently merged (cherry-pick candidates)`.

- [ ] **Step 3: Commit**

```bash
git add docs/upstream-triage/2026-05-17-todos.md
git commit -m "docs(triage): identify post-cutoff trunk merges as cherry-pick candidates"
```

## Task 6: Build the shortlist

The "Shortlist" header at the top of the artifact is what the maintainer reads first. Promote rows where `severity ∈ {S1, S2}` AND `relevance ∈ {R2, R3}` AND `action ∈ {A1, A2, A5}`.

- [ ] **Step 1: Re-read the full triage and pick survivors**

Open `2026-05-17-todos.md`. Anything tagged `A0` (already fixed / not applicable) drops out. Anything `S3` is included only if it's `A5` (a clean cherry-pick is cheap regardless of severity).

- [ ] **Step 2: Populate the shortlist section**

Use a tighter format for the shortlist — one bullet per item, no detail repeat:

```markdown
- **[S1/A1]** #NNNN — short title — _next step_
- **[S2/A5]** #MMMM — short title — _next step_
```

Order: S1s first, then S2s. Within a severity tier, `A1` (write code) before `A5` (cherry-pick) before `A2` (investigate).

- [ ] **Step 3: Commit and report**

```bash
git add docs/upstream-triage/2026-05-17-todos.md
git commit -m "docs(triage): shortlist the actionable upstream items"
```

Final deliverable: `docs/upstream-triage/2026-05-17-todos.md` with a populated Shortlist section. Print the shortlist back to the user as the task summary.

## Notes for re-running the sweep later

- The plan is parameterised on the date stamp `2026-05-17`. Future sweeps copy this file with the new date and run the same tasks.
- Keep the rubric stable across sweeps; if a row was tagged `S2/R2/A2` last time and is still untouched on our branch, it should classify identically on the next sweep — that's the consistency check.
- "Recently merged" cutoff moves forward each sweep to the previous sweep's date, not to our last `Merge branch 'trunk'` (otter-cache doesn't merge trunk routinely anymore).
